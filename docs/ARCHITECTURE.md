# Shared byte-range reconstruction architecture

## Canonical data path

Recovered files and optional image/map/DFXML → physical source catalogue → logical extent maps → streaming atom discovery → ordinary or fragmented reconstruction plan → structural assembly checks → optional strict packet/timing/full-decode validation → publication and typed job evidence.

`storage.Case` owns one SQLite database (`case.sqlite3`), lock, source catalogue, settings bindings, jobs, attempts and events. `ReaderPool` is the canonical recovery read path. It resolves logical offsets through `ranges.Extent` to checked regular physical sources, overlays acquisition maps and rejects unavailable ranges. Descriptor count is bounded. No missing range is zero-filled or removed to shift subsequent offsets.

`workflow.py` imports inputs, verifies PhotoRec headers, stages DFXML imports transactionally, and invokes the separate format strategies. `reports.py` streams case reports without collecting every job in memory. `cli.py` owns command dispatch only. The former independent fragmented database, lock and resume/report runner are removed.

`.DS_Store` is excluded through a shared path/source predicate before discovery,
registration, logical mapping intake, recovery reads and browser selection.
Historical catalogue rows are retained rather than deleting evidence or touching
the metadata file on disk.

Persisted source validation checks size, modification time and inode. A stored
operating-system device number is historical metadata, since a reboot/remount
can renumber it. A reader pins the current full filesystem identity and checks
path versus opened descriptor, including the current device number; changes
during that reader's lifetime still fail closed. Physical alias/overlap and tier
membership use the validated current device/inode pair. Historical sidecars
continue to describe their indexed source rows. Indexed full-file hashes remain
provenance; normal resume does not imply a new full-content hash of every source.

## Extents and acquisition

An extent records logical offset, physical source ID, physical offset and length. Mappings are sorted by logical position and validated for overlap, source-range reuse and bounds. Lookup is indexed with binary search; work is proportional to the intersecting extents. Gaps remain unavailable.

GNU ddrescue maps use explicit image = map position + offset translation. Only `+` is consumable with a map supplied; failed/untried/intermediate/uncovered ranges are unavailable. Files without mapped acquisition evidence are unknown. Mapfiles are evidence supplied by the operator, not cryptographic proof of original acquisition. Zero-valued bytes never establish rescue status.

`ranges.iter_dfxml` streams PhotoRec/fiwalk XML with limits on bytes, depth, fileobjects, runs and captured text. DTD/entities are forbidden. Raw `file_offset`/`offset`, `img_offset` and `len` values are checked against logical and image bounds. Fiwalk image offsets already include partition offsets. Sector padding is clipped to logical size. Sparse fills remain holes; compressed/resident data is unsupported. Filenames are labels, never export paths. A malformed trailing XML document rolls back staged mappings.

## Filesystem allocation scope

`recover --allocation-map PATH` loads a schema-1 `filesystem-unallocated` policy. Each physical image is bound by normalized absolute path, size and indexed SHA-256; its sorted image-relative byte ranges define eligible unallocated bytes. Missing image bindings, malformed ranges and identity changes fail closed. This is a supplied evidence policy, not a filesystem allocation detector. Operators must independently establish bitmap interpretation, active bitmap selection, partition origin and range provenance.

`ReaderPool` intersects this policy with logical extents and acquisition availability. It preflights the complete request before opening any media bytes, so a later excluded extent cannot cause an earlier partial read. Available-range iteration also intersects the policy, preventing deep-scan lookahead and fragmented-window reads from crossing excluded spans. Regular recovered files are unaffected. Reconstruction filters metadata and candidate headers. Complete mapped ranges are checked before accepted attempts are reused or exported. A sparse sample screen may reject an impossible candidate earlier, using allocation-gated reads and current source identities; its durable negative records explicitly state that complete range validation was not evaluated. Unavailable samples are not cached as malformed encoded bytes, so expanding an allocation or acquisition scope can reconsider them. Policy digests enter ordinary run keys. No source hash or atom index is regenerated by `recover`.

The index can contain allocated evidence from an earlier unrestricted scan without permitting new allocated image reads. Existing publications and their historical scope remain unchanged; applying a policy does not recertify them. A case with prior outputs therefore needs explicit historical-result accounting. Allocation identifies current filesystem ownership, not original recording integrity; allocated reference files must independently qualify before serving as reconstruction controls.

## Format specialists

`bmff.py` retains ordinary MP4 sample-table parsing and offset rewriting. `engine.py` retains whole-payload and scattered-extent hypotheses through the shared reader. Complete usable sample tables remain required; explicit filesystem maps can make physically split metadata/chunks logically readable. All encoded samples are preserved; reconstructed container metadata can differ from the original. Ordinary AVC standalone SEI samples are structurally classified and preserved. Optional `--reconstruct-only` bypasses codec subprocesses while retaining source/range/sample assembly checks, and publishes explicit reconstructed/non-decoded evidence. The default strict codec-validation behavior remains separate. Validator revisions participate in both cached-attempt eligibility and job run keys, so new acceptance rules do not reuse obsolete rejections.

`fragmented.py` retains narrow initialization, moof/traf/tfhd/trun and NAL validation. `image_recovery.py` discovers initialization locations in the shared catalogue and creates location-specific jobs. Equal headers remain separate locations. Unchanged completed coverage is checked from indexed locations before initialization media reads, while published hashes and current source identities are still verified. Later restarts with a present track missing its timing origin are rejected before reading the remaining section; a track absent from the first fragment can still appear later with explicit timing. It validates prefixes and separately assesses later independent starts up to the next initialization or source boundary, using bounded per-section reads. See FRAGMENTED.md.

FFmpeg remains the codec implementation. Independent packet hashes, exact timing and strict decoding validate candidates; they do not prove recording association. Acquisition status, association evidence and validation are separate manifest fields. Ordinary `matched`, fragmented `decoded_prefix`/segment outcomes, blocked/unsupported states and search limits retain their scope.

Default search policy enumerates eligible candidates in the first tier, excluding physical intervals already represented by accepted publications. Exclusions follow physical identity across aliases and mapped streams, while metadata remains readable and a resumed target can revalidate its own accepted intervals. Canonical jobs and publication provenance define the derived secondary membership; source files, atom indexes and prior accepted media remain intact. With `--include-recovered`, a target searches recovered references only after its first-tier whole/deep search yields no candidate. Job and sidecar scopes state searched tiers and whether second-tier evidence remains unsearched; first-tier uniqueness or absence is not a global claim. Optional finite search cutoffs preserve `search_limited` evidence. Ordinary catalogue identities and ordered whole-payload candidate locations are first snapshotted into private temporary SQLite storage. Case metadata is then loaded one movie at a time with completed point queries, so durable attempt commits do not retain a long-lived case read snapshot that prevents WAL recycling. Metadata BLOBs and candidate sets are not accumulated in Python memory. Uniform-offset hypotheses share a prepared read-only mapping plan; sparse rejection avoids rebuilding chunk assignments and sorting ranges for every candidate. Accepted mapping digests retain the canonical encoded representation. Translated sparse-negative keys are explicitly typed, source/scope-bound descriptors that avoid expanding all chunk rows; surviving candidates still receive the full allocation, source-range, overlap and encoded-byte proofs. Deep hits retain every physical location, including equal encoded content at different offsets, until physical compatibility is established. Cursor-based backtracking rejects overlapping partial assignments before expanding their remaining choices. Content prefixes expand only when a joint physical witness exists; a compatible witness is extended incrementally, with complete reassignment when a greedy extension fails. Each feasible content tuple is reconstructed once, while alternative locations remain available if a witness is unavailable. Final byte-identical outputs are deduplicated by their encoded bytes. Aliased logical sources cannot supply a second copy of the same physical bytes.

Extent-group capacity and a 32 MiB metadata budget schedule bounded batches instead of truncating the movie set. Ordinary matching checkpoints preliminary completion and deferred deep-search membership in canonical `ordinary_resume` rows qualified by run key and search tier. Result publication and queue-state updates commit together. Later traversals stream and reparse one indexed movie at a time; completed deep jobs are skipped after interruption. Whole-search limits and owner-specific revalidation remain attached to pending jobs. Completed source/profile structural discovery is reused, while an unfinished deep job may repeat. `ordinary_resume_runs` records whole-pass completion so `--retry` can distinguish resuming an interrupted pass from explicitly retrying a completed pass. Existing same-scope `awaiting_deep` records with explicit whole-search completion evidence are adopted into the durable queue without replaying preliminary matching. These additive scheduling tables do not alter the matching revision or invalidate source indexes. Uncapped discovery uses durable structural postings under `CASE/work/structural-index`, with source/range/parser identity and explicit completed coverage, including zero-hit sources. Current tier ownership is applied at candidate use rather than baked into the discovery evidence. Complete required anchor postings are intersected at their known group-relative offsets before full checks. Every discovery-bound source identity is rechecked, including sources yielding no locations; sample/range evidence remains authoritative at use. Explicit finite budgets retain the original nomination path and incomplete-result semantics. Alternative evidence summaries can still grow with actual ambiguity. See MATCHING.md for cache, concurrency and complexity contracts.

Accepted reference bookkeeping uses a shared owner-labelled physical interval index. Overlapping claims remain distinct, so exempting an output's own owner cannot expose another owner's claim. Changed owners update only their intervals and normalized `candidate_references` rows. The former derived `candidate_tiers` JSON is backed up locally in `settings` before conversion. Startup rebuilds derived references from verified publications rather than trusting cached rows. The exclusive case writer names the changed job during publication refresh, avoiding repeated scans of empty catalogue jobs; accepted publications and sources still receive fresh integrity checks. A full refresh discovers every job change.

Certified groups in uncapped indexed deep association also checkpoint exact
checked locations and all matching physical hits in
`work/association-checkpoint.sqlite3`. Bounded
transactions commit hits and their source/location cursor together. Independent
geometry receipts bind matching policy, source and map identities, allocation,
ownership and tier scope; incomplete coverage cannot establish absence or
uniqueness. Assembly can reuse complete association coverage after interruption,
while final reader, physical-witness and validation checks remain authoritative.
Per-group fingerprint aggregation and physical choices stream through their
backing database indexes; group-specific pruning remains an ephemeral overlay.
Completed batches retire their checkpoint data. Explicit finite budgets and raw
nomination paths retain their existing semantics. See [RESUMABILITY.md](RESUMABILITY.md)
for operator guidance and invalidation boundaries.

Each newly accepted output has an atomic JSON sidecar containing `ordered_fragments`: ordered output ranges, hashes, source logical ranges, bound physical extents and identities, plus track/chunk or fragment sequence information where available. Generated ordinary container bytes are distinguished from copied media. Existing publications are backfilled from verified retained chunk/fragment proof and bounded reads of their existing outputs; unavailable historical proof is explicitly flagged, never fabricated. A later narrower search preserves prior publication files and exposes them separately as historical outputs.

## Safety, state and migration

Inputs are regular read-only files. Case roots cannot contain inputs or overlap recovered-file trees. Metadata and source identities are bound to a case; consumed byte ranges carry hashes and provenance. Identity checks detect ordinary changes, not an adversarial administrator preserving inode/time metadata. The tool is not a hardware write blocker.

One case lock prevents concurrent writers. Outputs and evidence are verified before reuse. Missing generated media is restored before candidate-tier construction: an intact verified case copy is reused when available, otherwise the format owner rebuilds from retained ordinary chunk mappings or fragmented source ranges through the canonical reader. A shared materializer stages and verifies the accepted hash before installing an absent file. Existing changed files and unsafe paths are never replaced. Source identities, acquisition restrictions and final encoded-byte hashes remain authoritative. Byte-identical restoration preserves saved validation scope, job decisions and search checkpoints. Fragmented generated metadata can be recreated from committed job proof; absent ordinary mapping evidence remains an explicit reconstruction limitation. Interrupted uncommitted jobs are retried; conflicting existing publications stop recovery. Reports use private atomic writers; no external upload or source linking is performed. Case storage has no total quota; output/temp capacity remains an operator requirement.

Older schema/case layouts require explicit migration with a verified local SQLite backup (including WAL state). Historical outcomes preserve their original validation scope and do not acquire mapfile/extent guarantees. See LEGACY.md. Rollback uses the prior code with its original or backed-up case, never a new schema with old code.

## Evidence and limitations

Tests use generated media and disposable disk images, including noncontiguous mappings and unavailable ranges. Performance checks must distinguish interval lookup, mapping import, scan, validation subprocess and report costs. Passing synthetic fixtures does not establish original-image yield, all filesystem support, historical identity or wall-clock chronology. TEST_REPORT.md and the implementation plan record actual checks and unresolved gates.

## Progress reporting

`progress.py` owns command-scoped feedback shared by intake, scanning, recovery, validation, report generation, migration and tools. Library calls remain silent unless a reporting session is active. Phases report observed work with optional known totals; unknown discovery totals and opaque decoder waits never acquire artificial percentages. Assembly progress distinguishes checked/rejected physical assignments and content prefixes from considered content tuples and physical witness attempts; the Cartesian product is not used as a required-work denominator after pruning. Updates are throttled, streamed on stderr, and mirrored into case logs without changing machine results. Terminal phase states distinguish return, failure and interruption. Progress does not alter transaction boundaries, source reads, reconstruction decisions or search limits. Source labels distinguish recovered-file processing from allocation-unfiltered image indexing; availability maps do not establish filesystem-free space.
